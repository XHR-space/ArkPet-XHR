# 桌宠最终规格（已确认版）

本文件是**唯一权威规格**。任何实现、原型、评审都要以本文件为准；与旧计划冲突时以本文件为准。
来源：2026-11 用户确认的最终规则截图 + 仓库源码核对（`src/components/PetOverlay.tsx`、`src/views/WorkshopView.tsx`、`src/styles.css`）。

---

## 1. 固定显示

- 每只角色一个独立窗口。
- 角色舞台中心固定为显示框中心。
- 显示框位置固定、不可拖动。
- 显示框大小可调，允许裁掉角色。
- 角色显示缩放**不在**高级设置里单独调。
- 角色基础缩放（`pet.scale`）与桌面总缩放（`overlay.scale`）统一作用于显示、碰撞体积、交互范围。
- 编辑器始终显示归一化尺寸；实际桌面按缩放后的真实尺寸运行。

## 2. 两个独立矩形

| 类型 | 作用 |
| --- | --- |
| 碰撞体积 | 重力、落地、屏幕边界、任务栏、模组平台、角色互撞 |
| 交互范围 | 鼠标点击、拖动、右键；不参与物理 |

- 两个矩形都用像素级自由调整。
- 两个矩形对所有动画固定。
- 朝左、朝右时两个矩形一起水平镜像。
- 交互范围可以超出显示框；看不见的区域仍然可以点击、拖动。
- 两个矩形各管各的，不互相约束。

## 3. 默认值

- 碰撞体积、交互范围：按走路动画的整体范围生成。
- 交互范围默认复制碰撞体积。
- 显示框默认取所有动画的最大范围，避免裁切。
- 显示框之后可以手动调小或调大。

## 4. 世界物理

- 碰撞体积是唯一物理身体。
- 角色显示可以超出屏幕、被窗口遮挡或被裁掉。
- 碰撞体积不能出屏幕四边。
- 碰撞体积不能进入任务栏内部。
- 屏幕边界和任务栏是完整实心矩形：顶面可站，侧面阻挡。
- 没有任务栏的 macOS：屏幕四边作为碰撞边界，Dock 和菜单栏不参与碰撞与遮挡。
- Windows 任务栏即使自动隐藏，也一直保留碰撞体积。
- 只使用主显示器，不跨屏。

## 5. 模组物体

- 桌面图标、其他软件窗口、攀爬落脚点只有对应模组启用时才存在。
- 它们只提供顶面站立，不做侧面阻挡。
- 没装模组时，这些物体不参与物理。

## 6. 多角色

- 每只角色独立窗口，各自参与前后层级。
- 「相互穿过概率」继续使用现有设置。
- 概率命中：允许两个碰撞体积重叠，不主动改变前后层级。
- 概率未命中：只执行「碰撞后反向」，不强制推开重叠部分。
- 同一次相遇只判定一次，不每帧重复随机。

## 7. 窗口层级与鼠标

- 所有普通软件窗口都与桌宠比较真实前后层级。
- 前面的窗口遮挡角色显示，并优先接收点击。
- 桌宠在普通窗口层最前面启动，但永远被任务栏压住。
- 点击桌宠只把它带到前面，不默认抢键盘焦点。
- 打开文字对话、自动生成文字时，桌宠会临时抢焦点；点击其他窗口后焦点立刻被抢回。
- 桌宠窗口不出现在任务栏按钮和 Alt+Tab。
- 被前面窗口挡住时，桌宠物理、动画、自动行为继续运行。

## 8. 旧数据迁移

- 旧碰撞框**大小和偏移**迁移为新碰撞体积。
- 交互范围默认复制为新碰撞体积。
- 旧 `offsetX` / `offsetY` 不再参与定位，角色显示回舞台中心。
- 移除不再使用的「包含任务栏区域」死配置。

### 8.1 2.2.0 的几何事实（已核对源码，两处不一致是真实存在的）

- 运行时：宿主元素 = hitbox 矩形，位置 = `desktopPosition`；Spine 画布水平居中、底边贴宿主底边。
  → 显示框世界中心 = `desktopPosition + (hitboxWidth/2, hitboxHeight - displayFrameHeight/2)`。
  （`src/components/PetOverlay.tsx:1447-1460`、`src/styles.css` 的 `.multi-pet-visual` / `.multi-pet-spine`；
  落地判定用 `entity.y + entity.height`。）
- 编辑器：显示框居中在舞台中心，碰撞框画在显示框内部的 `((dw-hw)/2 + ox, (dh-hh)/2 + oy)`，而且
  `anchorBottom={false}`，sprite 摆放与运行时也不一致。
  → 碰撞框中心相对显示框中心 = `(hitboxOffsetX, hitboxOffsetY)`。
  （`src/views/WorkshopView.tsx:875-898 / 1095-1135`、`src/lib/renderConfig.ts:getHitboxPosition`。）

也就是说 2.2.0 里「编辑器里看到的碰撞框」和「运行时真正参与物理的身体」本来就不是同一个矩形。
迁移只能二选一，**用户已确认采用 A（host 口径）：升级后角色位置、落地状态都不变**。

### 8.2 迁移口径：**已确认采用 A（host 口径）**

| | **A. host 口径（已采用）** | B. editor-offset 口径（不采用） |
| --- | --- | --- |
| `collision.offset` | `(0, displayFrameHeight/2 - hitboxHeight/2)` | `(hitboxOffsetX, hitboxOffsetY)` |
| `placement` | `desktopPosition + 显示框世界中心` | `desktopPosition + 显示框世界中心 + 镜像后的 offset` |
| 含义 | 碰撞体 = 旧**运行时**那个身体 | 碰撞体 = 旧**编辑器**里那个框 |
| 升级后角色 | **位置、落地状态都不变** | 视觉锚点不变，但碰撞体会按差值下移/上移，随后被重力拉到地面 |
| fixture a（hitbox 96、display 323、oy 125） | offset `(0, 113.5)`、placement `(818, 1019)` | offset `(20, 125)`、placement `(838, 1030.5)` |
| 默认角色（oy = 0，display 320 / hitbox 134） | offset `(0, 93)`、落地状态不变 | offset `(0, 0)`，角色会相对地面下落约 93px |

两种口径下**显示框世界中心都不变**，所以「角色显示回舞台中心」这条都满足；差别只在碰撞体（也就是物理身体）落在哪里。

原型与 `electron/pet-layout.cjs` 都以 A 为默认；`geometryBasis: "editor-offset"` 仅用于对比复核，快照里会记录另一种口径的结果（`alternativePlacement`）。

### 8.3 其余迁移规则（无歧义，已定稿）

- `displayFrame` = `max(displayWidth, visualWidth) × max(displayHeight, visualHeight)`。
- 碰撞体大小 = 旧 `hitboxWidth × hitboxHeight`。
- `interaction` 默认完整复制 `collision`。
- 旧 `offsetX` / `offsetY`（sprite 偏移）不再参与定位。
- 朝左时 `offsetX` 取反（运行时镜像），存储值始终以朝右为基准。
- 删除不再使用的「包含任务栏区域」配置。
- 幂等：已带 `layoutVersion: 3` 的记录不得重算、不得改变 `placement`。
