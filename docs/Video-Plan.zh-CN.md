# ArkPet 产品介绍片 · 拍摄与制作规划

> 文档用途：在收到实际视频素材前，先确定全片目标、叙事结构、镜头覆盖、后期分工和素材交付规范。
>
> 内容范围：介绍 ArkPet 整套软件，不围绕某个版本做更新说明。成片中不出现版本号，不把一次版本改动当作核心卖点。

## 一、先确定片子的任务

### 1. 核心定位

ArkPet 是一个本地优先的 Windows 桌面角色工作台：

- 角色不只是静态壁纸，可以出现在桌面上行走、待机、掉落、被拖动和休眠。
- 每只桌宠都有独立状态，可以通过互动提升精力、主动性、关系和心情。
- 角色素材、角色档案、声音模块、本地模型和扩展模组可以由用户自己准备。
- 角色数据、声音样本和设置优先保存在本机；使用本地 AI 时不需要云端账号。
- 功能可以分层使用：不配置 AI 也能当桌宠；配置角色档案后可以文字对话；再接语音识别与合成后可以做语音对话。

全片一句话：

**ArkPet 把角色、人格、声音、状态和扩展能力组合成一套真正住在桌面上的角色系统。**

### 2. 目标观众

主观众是第一次接触 ArkPet 的普通用户。他们需要在开场很快理解三件事：

1. 屏幕上出现了什么。
2. 它和壁纸、普通聊天软件有什么区别。
3. 它可以怎样陪伴、互动和被定制。

次观众是愿意制作角色、配置 AI 或导入模组的高级用户。他们在中后段需要看到：

- 角色素材可以自己导入。
- 角色性格可以自己写。
- 声音可以根据自己的素材制作。
- 功能可以通过模块扩展。

### 3. 成片目标

观众看完主片后，应当能用自己的话说出：

> “这是一个能让原创角色住在 Windows 桌面上的工具。角色能走动和互动，也能有自己的性格和声音；我不配置 AI 也能先用，想深入时可以慢慢接本地模型和模组。”

这部片子不追求逐项讲完所有按钮，而是让观众建立完整、准确的产品认知。

## 二、叙事主轴

结构采用“先看见，再理解，最后相信”的顺序：

```text
角色出现
  -> 它真的住在桌面
  -> 它有自己的状态和相处方式
  -> 它可以是用户自己制作的角色
  -> 它可以拥有稳定的性格
  -> 它可以发出自己的声音
  -> 它可以继续扩展
  -> 所有重要的东西留在用户自己的电脑里
```

每一段只回答一个观众问题：

| 段落 | 观众问题 | 画面要证明的事 |
|---|---|---|
| 开场 | 这是什么？ | 一个角色真的在桌面上活动 |
| 桌面生活 | 和壁纸有什么区别？ | 会走路、掉落、拖动、休眠和互动 |
| 状态与陪伴 | 它会一直重复吗？ | 有精力、主动性、关系和经历记录 |
| 角色制作 | 只能用自带角色吗？ | 可以导入 Spine 角色并绑定动作 |
| 性格与对话 | 它会说自己的话吗？ | 角色档案控制身份、性格和表达 |
| 声音 | 它能用自己的声音说话吗？ | 声音模块接入识别、生成和合成链路 |
| 扩展 | 以后还能增加功能吗？ | 官方模组、自模组和角色绑定 |
| 数据与收尾 | 我的东西在哪里？ | 本地保存、可备份、可恢复 |

## 三、内容优先级

### 必须展示

- 桌宠从管理台释放到桌面。
- 行走、待机、拖动、落地、休眠等桌面行为。
- 鼠标穿透和右键菜单，说明它不会阻挡正常工作。
- 首页的角色状态，包括精力、主动性、关系、心情和陪伴时间。
- 导入 Spine 角色和绑定基础动作。
- 角色档案和文字对话。
- 声音模块和完整语音对话链路。
- 模组安装、导入或绑定到角色的流程。
- 本地数据、备份和软件更新保留用户数据。

### 可以展示

- 多只桌宠同时上桌。
- 自动文字和自动语音。
- 重力锁定、速度、摩擦、弹性和显示大小等行为参数。
- 角色位置、碰撞区域和显示画面三种高级调试模式。
- 资料与长期记忆。
- 模型管理中的本地模式和 API 模式。
- 四套界面主题。
- 角色预录语音和语音训练。

### 不在主片展开

- 安装步骤的完整点击流程。
- 模组开发接口清单。
- 复杂文件格式规则。
- 更新服务器、发布种子和程序目录结构。
- 只对维护者有意义的技术实现。
- 版本号和更新日志。

## 四、主片结构

建议主片时长控制在 2 分 30 秒左右，预留上下浮动空间。后续剪辑时可以按实际素材删减，不强行凑满时间。

| 段落 | 建议时长 | 核心内容 | 主要素材 |
|---|---:|---|---|
| 0. 冷开场 | 0:08 | 角色走进桌面，建立第一眼印象 | 干净桌面实拍录屏 + 标题动画 |
| 1. 产品定义 | 0:15 | 说明它是桌面角色工作台，不是壁纸或普通聊天框 | 管理台首页、角色特写、界面关键卡片 |
| 2. 桌面生活 | 0:30 | 释放、行走、拖动、落地、任务栏、右键菜单、鼠标穿透 | 桌面实拍录屏为主 |
| 3. 状态与陪伴 | 0:18 | 精力、主动性、关系、心情、经历、陪伴时长 | 首页总览、互动前后变化 |
| 4. 制作角色 | 0:22 | Spine 导入、动作绑定、尺寸和碰撞调整 | 桌宠唤醒界面 + 角色动作预览 |
| 5. 角色人格 | 0:22 | 角色档案、资料、记忆、文字对话 | 档案编辑、文字对话逐字回复 |
| 6. 声音与语音对话 | 0:25 | 声音模块、声音样本、识别、生成、合成、播放 | 声音模块、模型管理、完整语音对话 |
| 7. 模组扩展 | 0:18 | 官方模组、本地导入、绑定角色、右键入口 | 模组管理 + 右键菜单 |
| 8. 数据与收尾 | 0:18 | 主题、备份、恢复、本地保存、更新保留数据 | 数据与设置 + 片尾角色镜头 |

主片总长可按素材质量调整到 2 分 10 秒到 2 分 50 秒。

## 五、逐段镜头规划

### 0. 冷开场

**目的**

先让观众看到“一个角色真的住在桌面”，不要先解释概念。

**画面**

1. 干净桌面，鼠标缓慢移动。
2. 角色从屏幕边缘走入画面。
3. 角色停住、待机或做一个小动作。
4. 标题淡入：`ArkPet`、`本地角色工作台`。

**旁白要点**

- 你的桌面上，可以住着一个真正的角色。

**拍摄重点**

- 不要在开头先放 Logo。
- 前几秒必须看到角色本体，而不是只有 UI 或标题卡。
- 桌面图标、通知和无关窗口提前清理。

### 1. 产品定义

**目的**

回答“这不是普通壁纸，也不是普通聊天软件”。

**画面**

1. 管理台整体界面。
2. 快速经过六个主导航。
3. 首页角色卡、状态条和桌面陪伴时间。

**旁白要点**

- ArkPet 把角色、人格、声音、状态和扩展能力放在同一套工作台里。
- 角色住在桌面上，设置和数据留在本机。

**屏幕文字建议**

```text
角色
状态
人格
声音
扩展
本地数据
```

### 2. 桌面生活

**目的**

证明 ArkPet 的核心体验发生在桌面，而不是只发生在管理台里。

**必须拍到的镜头**

1. 点击“从窗口释放”，管理台后退，角色出现在桌面。
2. 角色正常行走。
3. 按住角色拖动，显示“被抓”动作。
4. 松手后角色掉落、落地、弹跳或停稳。
5. 角色沿任务栏或桌面边缘活动。
6. 点击角色，保持正常互动，不抢走其他软件焦点。
7. 右键角色，弹出菜单。
8. 选择“桌面休眠”。
9. 选择“收回并休眠”。

**旁白要点**

- 角色会走动、掉落、被拖动，也会在任务栏附近活动。
- 只有角色实际占用的区域接收操作，其余位置鼠标穿透。
- 不使用时可以休眠或收回。

**后期表现**

- 点击位置加一次短暂环形高亮。
- 拖动和落地处放慢到 0.6 倍左右。
- 鼠标穿透用一小块桌面区域和鼠标移动来证明，不靠大段解释。

### 3. 状态与陪伴

**目的**

说明桌宠不是无限循环动画，而是有连续状态和相处过程。

**画面**

1. 首页总览。
2. 精力、主动性、关系和心情。
3. 今日桌面陪伴时间和累计时间。
4. 最近经历。
5. 点击“聊一会儿”“让它休息”或互动按钮后的状态变化。

**旁白要点**

- 每只桌宠有自己的精力、主动性、关系和经历。
- 互动会影响状态，状态又会改变角色当前的表现。
- 首页可以快速看到这只角色最近是怎么陪你度过的。

### 4. 制作角色

**目的**

说明 ArkPet 不只提供预设角色，也可以成为原创角色的桌面载体。

**画面**

1. 打开“桌宠唤醒”。
2. 新增桌宠。
3. 导入骨骼文件、图集文件和纹理 PNG。
4. 显示检测到的动画。
5. 依次绑定待机、走路、掉落、落地、被抓和休眠。
6. 预览动作。
7. 打开高级设置，展示角色位置、碰撞区域和显示画面。
8. 调整角色大小或碰撞框，保存后回到桌面。

**旁白要点**

- 可以导入 Spine 角色素材。
- 把动作绑定到正确的状态后，角色就能在桌面上以对应方式行动。
- 显示画面和碰撞区域可以单独调整，让点击区域贴住角色身体。

**真实性约束**

- 明确说明是 Spine 骨骼角色，不暗示支持任意格式。
- 不把高级调试框表现得像普通用户必须完成的长流程。

### 5. 角色人格

**目的**

回答“它会说自己的话吗”，并区分“角色档案”和“运行时状态”。

**画面**

1. 角色档案编辑区。
2. 填入身份、性格、说话方式、世界观、喜恶和关系边界。
3. 展示角色 Skill 或运行时 Prompt 预览。
4. 添加一份资料或一条长期记忆。
5. 输入一句话进行文字对话。
6. 角色回复逐字出现，内容和角色设定一致。
7. 展示无模型时的内置角色回应提示。

**旁白要点**

- 角色档案决定它是谁，以及它会怎样说话。
- 精力、主动性和关系是运行时状态，会改变表达方式，不会覆盖角色本身。
- 可以先做文字对话测试，再决定是否接入本地模型。

### 6. 声音与语音对话

**目的**

展示从“有文字人格”到“能用自己的声音说话”的完整链路。

**画面**

1. 打开“声音模块”。
2. 新建声音模块。
3. 导入声音样本或参考音频。
4. 填写参考音频原话。
5. 选择语音合成引擎或声线。
6. 播放测试音频。
7. 打开“模型管理”，展示语音合成、语音识别和对话模型三种能力。
8. 绑定声音模块和角色档案。
9. 右键角色，选择“语音对话”。
10. 完成一次录音、识别、生成、合成和播放。

**旁白要点**

- 声音模块决定角色怎样发声，角色档案决定它说什么。
- 本地模式、语音识别和语音合成组成完整的语音对话链路。
- 大型模型和声音权重由用户自己准备，软件不宣称开箱自带全部模型。

**画面链路**

```text
麦克风录音
  -> ASR 语音识别
  -> LLM 按角色档案生成回复
  -> TTS 用绑定声线合成
  -> 播放语音
```

### 7. 模组扩展

**目的**

说明 ArkPet 的功能边界可以继续扩展。

**画面**

1. 模组管理整体界面。
2. 官方模组库。
3. 安装、更新或启用一个模组。
4. 导入本地模组文件夹或压缩包。
5. 回到桌宠设置，把模组绑定给某只角色。
6. 右键角色，菜单中出现该模组入口。
7. 打开模组页面或触发对应效果。

**旁白要点**

- 官方模组可以独立下载和更新。
- 本地模组可以导入并绑定给指定角色。
- 绑定后的入口会进入角色右键菜单，功能围绕角色出现。

### 8. 数据与收尾

**目的**

把整片收束到“这是用户可以长期使用的本地角色系统”。

**画面**

1. 数据与设置。
2. 数据目录和用户数据目录。
3. 导出备份、导入备份和打开角色存档。
4. 四套主题快速切换。
5. 自动更新界面，强调更新保留用户数据。
6. 回到桌面，角色走向镜头并停下。

**片尾文字**

```text
ArkPet
让角色，真正住进桌面。
```

**旁白要点**

- 角色档案、声音样本、模型路径和对话设置保存在本机。
- 更新程序不会主动删除用户数据。
- 需要换电脑时，可以导出备份再恢复。

## 六、成片版本

### 1. 主片

- 目标时长：2 分 10 秒到 2 分 50 秒。
- 画幅：16:9，优先 1920×1080。
- 用途：官网、GitHub、完整功能介绍、演示视频。

### 2. 90 秒精简版

只保留四件事：

1. 角色在桌面上活动。
2. 角色可以被拖动、右键和休眠。
3. 角色可以自己制作，也可以拥有性格和声音。
4. 数据和角色内容留在本机。

### 3. 30 秒宣传版

结构：

| 时间 | 内容 |
|---|---|
| 0-5 秒 | 角色走进桌面 + ArkPet 标题 |
| 5-13 秒 | 拖动、落地、右键菜单 |
| 13-22 秒 | 角色档案、文字回复、声音 |
| 22-26 秒 | 模组入口一闪 |
| 26-30 秒 | 本地数据 + 片尾标语 |

### 4. 9:16 竖版

- 从主片重新取景，不直接压缩 16:9 画面。
- 桌面交互镜头尽量使用局部放大。
- 字幕放在角色和操作区域之外。
- 一屏最多保留一个主要操作动作。

## 七、你后续提供的素材要求

收到素材后，我会先做可用性检查，再进入粗剪。为了减少补拍，建议按以下规格拍摄。

### 1. 录屏规格

- 分辨率：1920×1080 或更高。
- 帧率：60fps。
- Windows 显示缩放：100%。
- 使用整屏捕获，不要只捕获应用窗口。
- 需要包含鼠标指针。
- 不提前加字幕、音乐、转场或滤镜。
- 每段单独录制，不要从安装一直录到最后。

### 2. 画面环境

- 使用统一壁纸。
- 隐藏桌面图标。
- 关闭通知、聊天软件和无关弹窗。
- 任务栏保持干净。
- 角色、窗口和鼠标都不要被输入法候选框遮挡。
- 如素材包含私人路径、账号、聊天内容或文件名，提前打码或换演示数据。

### 3. 单段素材长度

- 每个关键操作前后各留 2 到 3 秒。
- 每次点击前停约 0.5 秒。
- 单段控制在 8 到 25 秒，方便后期挑选。
- 同一动作如果时机不稳，至少拍 2 到 3 条。

## 九、制作分工

| 工作 | 方式 |
|---|---|
| 桌面行为、按钮操作、实际对话 | 真实屏幕录制 |
| 角色特写、桌面陪伴氛围 | 可选实拍素材 |
| 标题、关键词、链路图、片尾 | 动效模板合成 |
| 素材拼接、节奏、缩放、高亮、字幕 | 后期时间线剪辑 |
| 多比例和短版导出 | 按主时间线复用 |
| 旁白 | 真人录音或 TTS，均需保留单独音轨 |
| 配乐 | 使用无版权争议的音乐，不盖住语音 |

## 十、避免失真的表达

介绍片需要准确，不把可选能力说成默认能力，也不把高级功能说成零配置体验。

- 不说“开箱即用大模型”。软件提供的是接入和配置能力，大模型、语音权重和引擎需要用户自行准备。
- 不说“所有行为都会上传云端”。默认强调本地保存；同时注意 API 模式会访问用户配置的远程服务。
- 不说“支持所有动画角色格式”。当前角色制作围绕 Spine 骨骼素材展开。
- 不说“任何声音都能立刻完美复刻”。声音模块依赖样本、参考音频和合成引擎。
- 不把模组开发接口放进主片。普通观众只需要理解“可以安装、导入和扩展”。
- 不用版本号作为卖点。软件能力用完整产品视角介绍。

## 十一、后期验收标准

- [ ] 前 10 秒能看见角色，不只看见 UI。
- [ ] 前 20 秒说清“桌面角色工作台”和“角色住在桌面上”。
- [ ] 桌面交互段落能看出拖动、落地、任务栏、右键和鼠标穿透。
- [ ] 每个重点功能都有真实操作画面，没有只靠文字卡说明。
- [ ] 普通用户能看懂基础陪伴流程。
- [ ] 高级用户能看出角色、人格、声音和模组的自定义能力。
- [ ] 全片没有版本号或临时更新信息。
- [ ] 明确表达模型需要用户准备，避免误解。
- [ ] 字幕不遮挡角色和操作焦点。
- [ ] 竖版重新取景，不把横版直接塞进中间。
- [ ] 旁白、音乐和音效分别保留可调整音轨。
